# Karenya Mini Games

兩款獨立小遊戲的公開原型規格與待認領工作。此 repo 目前只有文件，沒有可執行遊戲；run/build/test、操作驗證與遊戲截圖均尚未產生。

## 原型

| 遊戲 | 目錄與規格 | 核心體驗 |
| --- | --- | --- |
| 魔女的行李箱 | [games/witch-suitcase/BRIEF.md](games/witch-suitcase/BRIEF.md) | 六件有個性的物品，以平面拖曳、旋轉、吸附整理行李，觀察互動規則與結局。 |
| 借一扇窗 | [games/borrow-a-window/BRIEF.md](games/borrow-a-window/BRIEF.md) | 一扇窗、三層景深與 30 秒循環，在受限視角中探索固定的小型互動點。 |

兩案各自保有程式、依賴、操作說明與驗證證據。先完成灰盒；不先建立共用框架、物理引擎、後端或付費 SDK。不匯入私人 Studio、Bot、小說資料、素材、歷史、秘密或私人 issue 連結。

## 認領與接棒

1. **Grok 待認領**：GitHub issue 是公開工作單。角色名稱不是 GitHub 帳號；待認領不等於已通知、已接受或已開工。沒有自動指派，也不呼叫外部 AI。
2. **單一 owner 灰盒實作**：認領者在工作單記錄經確認的 GitHub 帳號、工作範圍、feature branch、候選規則決策與驗收計畫。每案同一時間只有一位 owner；他人加入須先協調。
3. **GPT 驗收**：owner 提交完整 commit 與下列實測證據後，由 GPT 檢查玩法、幾何／互動、可達性、reset 與規格符合程度；記錄通過與未通過項目。角色稱呼不代表已有評審自動執行。
4. **Claude 可明確接棒**：工作單明載接棒範圍、最後 commit、分支、重現步驟、未完成事項及 owner 交接狀態，經接手者確認後才算接棒。

後續遊戲實作必須使用 feature branch，提供完整 commit SHA 與可檢視差異。新 repo 的這次乾淨文件初始化可直接提交預設分支；不操作其他 repo 的 main/dev。

## 實作交付與驗收證據

- 提供該案安裝、run/build/test 的實際指令、環境版本、退出碼與結果。未執行或沒有適用測試時明說，不以預期結果充當實測。
- 提供桌面滑鼠及 touch 的瀏覽器／裝置、操作步驟、預期與實際結果；涵蓋重複操作、reset 及該案 BRIEF 的特定案例。
- 提供灰盒截圖與必要的操作錄影／重現紀錄；畫面不得帶入秘密或私人資料。附上 known limits/TODO、缺陷重現步驟與接棒說明。
- 原型可玩驗收與最終 UIUX／美術是不同審查階段；灰盒通過不代表最終視覺已通過。

## 發布與授權
